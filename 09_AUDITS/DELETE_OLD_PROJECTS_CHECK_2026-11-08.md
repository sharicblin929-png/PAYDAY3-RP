# Готовность PAYDAY3-RP к удалению старых GitHub/Notion архивов — 2026-11-08

## Область гарантии
**Проверяется возможность вести новую PAYDAY RPG**, а не сохранение всего материала других игр. Если удалить прежние репозитории/страницы, подробная история *тех* сюжетов исчезнет, если её не сохранить отдельно.

## Новые независимые рабочие ресурсы
- GitHub: [PAYDAY3-RP](https://github.com/sharicblin929-png/PAYDAY3-RP), ветка main, `CURRENT`, `RULES`, `RUNBOOK`, `START_HERE`.
- Notion: [самостоятельный корневой архив PAYDAY](https://app.notion.com/p/4126d0e9324981e9ae7edbb038bd70f9?pvs=204) с девятью собственными рабочими разделами.
- [Полная схема адресов и синхронизации](../00_SYSTEM/NOTION_ARCHIVE.md).

## Структурный контроль
- [x] Канон Circle, NPC, мира, общего убежища, правила боя/стелса, экономики и сюжета расположены в PAYDAY.
- [x] Сведения об истинном уровне технической практики, учебный маршрут, открытый каталог ресурсов перенесены в PAYDAY.
- [x] Ни один обязательный рабочий файл PAYDAY не ссылается на прежний приватный GitHub или Notion как на источник истины.
- [x] Протокол брифингов требует детальные графические схемы улиц, объектов и отдельных этажей, создаваемые во время реального брифинга.
- [x] GitHub имеет собственные хронику и правила сейвов, Notion имеет шаблоны будущих GM/сейвов и отдельное место для них.
- [x] Три чата PAYDAY стартуют только из нового GitHub.
- [x] Notion-архив создали **новой корневой приватной страницей**, не в пространстве страниц предыдущих игр.
- [x] Пустые поля героя (маска, стартовые суммы, дата) НЕ заполнены произвольно, несуществующие GM и миссии не сочинены.
- [x] Из старых приватных репозиториев не копировались чувствительные данные или неотносящиеся к PAYDAY сюжетные архивы в публичный GitHub.

## Чего НЕ делает эта подготовка
- Не сохраняет всю историю Cyberpunk и STALKER; она не нужна для игры PAYDAY, но может быть нужна пользователю по другим причинам.
- Не делает автоматическую синхронизацию Notion↔GitHub: после каждого действия ведущая **адресно** пишет в оба сервиса (GitHub первый) при наличии доступа.
- Не доказывает, что внешние автоматизации/ссылки за пределами PAYDAY не зависят от удаляемых ресурсов.
- Не закрывает пока ещё **не определённые игроком** характеристики: маска, стартовое время, деньги, хранилище, обстоятельства встречи.
- Не удаляет старые материалы и не выдаёт это за сделанное.

## Краткий контрольный список самого пользователя перед удалением
- [ ] Если хоть немного важна история «Рихтера»/«Пророка», скачать ZIP/сделать `git clone --mirror` старых репозиториев, а в Notion экспортировать соответствующие старые страницы с дочерними страницами; проверить наличие файлов.
- [ ] Удалять **только старые корневые Notion-ветки**, не трогая PAYDAY-хаб или весь workspace. Новая PAYDAY-страница должна оставаться доступной отдельно.
- [ ] При необходимости проверить свои закладки, сторонние автоматизации и ссылки на старые репозитории — они могут перестать работать.
- [ ] После удаления ещё раз открыть GitHub `START_HERE`, `CURRENT`, Notion PAYDAY-хаб и одну учебную карточку.

## Вердикт
Новая PAYDAY RPG имеет самостоятельный полный рабочий контекст для начала и ведения игры **без старых RPG**, в двух сервисах. Право выбора удалить старые истории принадлежит пользователю; резервирование их собственной информации — отдельное решение.
