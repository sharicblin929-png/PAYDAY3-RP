# RUNBOOK — компактный рабочий цикл PAYDAY3-RP

**Операционный источник:** [CURRENT](CURRENT.md) (что происходит сейчас), [RULES](RULES.md) (постоянные договорённости), [START_HERE](START_HERE.md) (режим чата). **При позднем игровом контенте/броне/оружии по сцене** обратиться к [CONTENT_POOL](../01_WORLD/CONTENT_POOL.md), но не на каждом обычном GM. **Не читать старые аудиты и другие RPG перед каждым постом.**

## Три отдельных чата
- **RPG:** только здесь живёт каноническая сцена, общение с бандой, ограбления, последствия и игровые транзакции. После каждого **завершённого** ответа GM — подтверждённая запись в GitHub и короткое зеркало Notion.
- **МАШИНЫ:** реальная учёба по [PROGRESS](../04_LEARNING/PROGRESS.md) и [ROADMAP](../04_LEARNING/ROADMAP.md), на собственных/разрешённых THM/CTF стендах. **Никаких GM, не двигать сюжет/деньги, не делать репозиторных записей.**
- **ТЕХНИКА И ПРАВКИ:** проверка и адресная правка файлов, без запуска игровой сцены и без выдуманных событий.

## Перед каждым RPG-постом
1. Перед **КАЖДЫМ** ответом прочитать короткий [CURRENT](CURRENT.md), [KNOWLEDGE_SNAPSHOT](../01_WORLD/NPC_KNOWLEDGE_LEDGER.md) для присутствующих/обсуждаемых персонажей и **последний завершённый** GM (сейчас [GM-0020](../06_CHRONICLE/GM-0020.md); после хода использовать новую ссылку из CURRENT). При первом входе в чат прочитать [RULES](RULES.md), затем не загружать их целиком без причины. **Эти три источника обязательны, а не декоративные**.
2. Адресно открыть досье **только участвующего** NPC из [канона](../01_WORLD/CHARACTER_CANON_REGISTER.md), если нужны характер/биография; его **фактические знания читать в компактном snapshot из шага 1**; при операции — активные брифинг/карты и [TACTICAL STATE](../03_HEISTS/TACTICAL_STATE_TEMPLATE.md), при изменениях оружия/денег — [GEAR](../05_ECONOMY/GEAR_REGISTER.md), [LEDGER](../05_ECONOMY/LEDGER.md). Цены — только если они нужны. **Не читать весь репозиторий**.
3. Проверить время/позиции/ресурсы/агентность; **не играть за Circle**, не давать NPC всеведения, не назначать Dallas командиром автоматически. **Перед ЛЮБЫМ неожиданным раскрытием выполнить `REVELATION_CHECK`: (a) сформулировать факт P; (b) проверить `FACT_LOCKS` в CURRENT и `K##/J##` в KNOWLEDGE_SNAPSHOT; (c) кто уже знает P и с какого GM; (d) лишь если P действительно новый ДЛЯ этого персонажа, писать первую реакцию.** В противном случае вести сцену как разговор об **уже известном**. Чужая гипотеза или услышанное заявление не равно проверенному факту.
4. Сохранить утверждённую сюжетную защиту: **никаких смертей или полного провала взятого ограбления**, только мелкие/средние нефатальные осложнения/потери/возможный арест. После вступления Circle выполняет **назначенные** миссии; сомнения и сопротивление — сюжетные решения героя, не «бесплатная отмена контракта».
5. Соразмерять длительность ответа с действием игрока; важную развилку не перескакивать. **Говорить за NPC естественно и просто, без пафоса и сложных оборотов; не растягивать пост без необходимости.** Сохранять индивидуальные голоса персонажей; не повторять тезис игрока перед ответом. [Полное правило стиля](RULES.md). Результат определяется обстоятельствами, ограниченная случайность — только в неоднозначных исходах, не нарушая сюжетных границ.

## Особые сцены
- **Перед каждым новым ограблением:** полный подробный **визуальный** брифинг с улицей, значимыми объектами, всеми известными этажами отдельно и текстом по [стандарту карт](../03_HEISTS/BRIEFING_MAP_STANDARD.md). Подготовить по реальным известным банде данным, не открывать неведомое; утвердить экипировку, числа магазинов/патронов/зарядов до выезда. Назначить роли по обстоятельствам/компетенциям, не автоматически по статусу Dallas.
- **Техническая задача:** когда задача реально появляется в сцене, дать **2–3 кратких направления**; игрок выбирает или предлагает своё. Если нужен новый навык, обучение идёт в чате МАШИНЫ на **разрешённом** стенде; знакомое не пересдавать и сюжет без повода не останавливать.
- **Бой или напряжённая скрытность:** короткое состояние/позиции/расход; полную карту повторно не публиковать. Не забегать за следующий выбор Circle.

## После завершённого GM
1. Создать **полный неизменяемый** `06_CHRONICLE/GM-XXXX.md`; **ПЕРЕЗАПИСАТЬ** короткий `CURRENT` только актуальной сценой, меняющимися FACT_LOCKS и открытыми U##, **НЕ дописывать `- GM-XXXX / сейчас` за каждый пост**. Изменить `KNOWLEDGE_SNAPSHOT` только при новом знании/убеждении/отношении NPC, с `GM`-источником; **не раздувать его посценовыми пересказами**. Обновить только затронутые GEAR/LEDGER/STATE. **Один атомарный коммит** для всех изменений этого GM; проверить чтением GitHub и актуальный номер, не утверждать успех раньше проверки.
2. В [Notion](NOTION_ARCHIVE.md) **обновить только короткие рабочие карточки** и добавить **одну строку в существующий индекс 07 HISTORY** со ссылкой на полный GitHub-GM. **Никакой новой полной Notion-страницы на каждый GM**; проверить отсутствие дублей и результат, при недоступности назвать несинхронизированное.
3. После **каждых 20 завершённых GM** и ключевых переходов — независимый переносимый `07_SAVES/` checkpoint, не перезаписывать прежний. О смене крупной главы предупредить OOC до перескока.
4. Оборванная/прерванная генерация — **не канон**; выявленную ошибку явно исправить, без скрытых ретконов и создания лишних GM/папок.

**Секреты не сохранять в публичный GitHub.** Другие RPG-репозитории и их Notion-страницы не нужны. Нет фонового зеркалирования — только сделанное в текущем ходе при доступности сервисов.
