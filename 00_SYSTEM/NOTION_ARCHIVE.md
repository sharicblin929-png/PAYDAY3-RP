## Автономная иерархия
Все девять страниц расположены **под новым корневым PAYDAY-хабом**. Они не являются потомками корневых страниц Cyberpunk или S.T.A.L.K.E.R. Удаление старых Notion-веток не должно удалять новый PAYDAY-хаб, **если не удалять общий более высокий контейнер всего workspace**.

**Канонические характеры персонажей (включая источники из интернета):** [CHARACTER_CANON_REGISTER](../01_WORLD/CHARACTER_CANON_REGISTER.md). **Текущее снаряжение и боезапас:** [GEAR_REGISTER](../05_ECONOMY/GEAR_REGISTER.md). **Боевой шаблон:** [TACTICAL_STATE_TEMPLATE](../03_HEISTS/TACTICAL_STATE_TEMPLATE.md). Эти файлы являются специализированными актуальными реестрами; Notion 03/06 и оперативные страницы миссии — зеркало, не новая параллельная система.

**Цена оружия и исторические стоимости сумок из интернета:** [PRICE_REFERENCE_2023](../05_ECONOMY/PRICE_REFERENCE_2023.md) с датами и метками подтверждения/оценки. Notion 06 хранит короткие ориентиры, полный список — только в этом файле.

## Единый протокол синхронизации
1. **GitHub — канонический источник истины**: `CURRENT.md`, `RULES.md`, нужные досье/реестры, `06_CHRONICLE/GM-xxxx.md`, `07_SAVES/`.
2. Перед GM читать текущую сцену/состояние из GitHub; при необходимости Notion для удобства, но **не вместо** подтверждённого GitHub.
3. После сыгранного поста записать GitHub и проверить чтением. Затем адресно изменить карточку 00 CURRENT и только реально затронутые карточки 02–06; добавить **только одну строку GM-XXXX со ссылкой на полный GitHub-пост в существующий индекс 07 HISTORY** (не отдельную страницу на каждый пост); на контрольных точках создать самостоятельный сейв. Проверить результат Notion.
4. **Нет фоновой синхронизации**: работа выполняется при текущем ходе/запросе с доступным инструментом. Ошибка записи Notion не является потерей GitHub-канона; сообщить о частичном сохранении. Ошибка GitHub — не выдавать общий сейв за полный.
5. В техническом чате никакой записи на уровне игрового GM. Подтверждённый учебный результат переносится в основной рабочий чат и обновляет GitHub PROGRESS и Notion 05.

## Новые записи в будущем
- **Новая миссия:** в GitHub `03_HEISTS/H-XX_.../`, **дочерняя страница** Notion под 04 HEISTS. Пакет карт (SVG/изображение), улица/квартал/важные объекты, **каждый этаж отдельно**, с отмеченной неизвестностью. **Не генерировать карты задним числом или без брифинга**.
- **После GM:** полный пост в GitHub `06_CHRONICLE/GM-XXXX.md`; короткая строка в существующем индексе Notion 07 HISTORY. Это НЕ второй полный архив художественных постов.
- **Сейв:** отдельная страница Notion лишь каждые 20 завершённых GM и после ключевого эпизода — GitHub `07_SAVES/SAVE_AFTER_GM-XXXX.md`, дочерняя Notion под 07 HISTORY.
- **Новый NPC:** сначала нужное поле `01_WORLD/NPC_KNOWLEDGE_LEDGER.md` и Notion 03; отдельное досье только если реально понадобится.
- **Обновление учёбы:** только проверенная практика, не автоматически успешное лабораторное задание.

## Правила удаления старых ресурсов
После подготовительного аудита старые Notion-страницы и GitHub-репозитории можно удалять **без потери способности вести PAYDAY**, но **с потерей их собственных игровых архивов**, если не сделать отдельные резервные копии. Не удалять чужие старые страницы/репозитории автоматически. [Проверка перед удалением](../09_AUDITS/DELETE_OLD_PROJECTS_CHECK_2026-11-08.md).

**Секреты:** GitHub-репозиторий PAYDAY публичный; ни туда, ни в оперативную историю не переносить настоящие логины, токены, персональные данные и чувствительные логи.
